# Claude Code Tab Session 调试指南

## 概述

本指南帮助您调试 Claude Code 的 Tab 级 Session 功能，特别是解决 chansend 相关的问题。

## 设置步骤

### 1. 配置 Tab 模式

在 Neovim 配置中添加：

```lua
require("claudecode").setup({
  terminal = {
    session_scope = "tab"  -- 启用 Tab 级 Session
  },
  log_level = "debug"  -- 启用调试日志
})
```

### 2. 清理旧日志

```bash
/Users/pittcat/.vim/plugged/claudecode.nvim/log/clear_logs.sh
```

### 3. 启动调试

```bash
# 在一个终端中实时查看日志
tail -f /Users/pittcat/.vim/plugged/claudecode.nvim/log/debug.log

# 或者使用我们的脚本
/Users/pittcat/.vim/plugged/claudecode.nvim/log/view_logs.sh
```

## 测试步骤

1. **打开 Neovim**
2. **创建两个标签页**:
   ```vim
   :tabnew
   :tabnew
   ```

3. **在标签页 1 中启动 Claude Code**:
   ```vim
   :ClaudeCodeStart
   ```

4. **在标签页 2 中启动 Claude Code**:
   ```vim
   :ClaudeCodeStart
   ```

5. **在标签页 1 中触发 @mention**:
   - 选择一个文件
   - 运行 `:ClaudeCodeAtMention`

6. **检查日志**，确认消息只发送到标签页 1

7. **在标签页 2 中触发 @mention**
8. **再次检查日志**，确认消息只发送到标签页 2

### 错误情况分析

#### 问题 1: job_id 未找到

**症状**: 日志显示 `[GET-JOB-CHANNEL] No job_id found, returning nil`

**解决方案**:
1. 查看日志中的 "Available terminal properties" 部分
2. 找到存储 job_id 的正确位置
3. 更新 `terminal/snacks.lua` 中的 `get_job_channel()` 函数

#### 问题 2: 提供者加载失败

**症状**: 日志显示 `[GET-PROVIDER] Snacks provider not available, falling back to native`

**解决方案**:
1. 检查 Snacks.nvim 是否已安装
2. 验证 `terminal.provider` 配置
3. 考虑回退到 `native` 提供者

#### 问题 3: chansend 失败

**症状**: 日志显示 `[CHANSEND-TAB] chansend result - ok: false`

**解决方案**:
1. 检查 job_channel 是否有效
2. 验证 vim.fn.chansend 的参数
3. 确认终端进程是否仍在运行

## 常见问题

### Q: 如何知道当前使用的是哪个提供者？

A: 查看日志中的 `[GET-PROVIDER]` 消息：
- `[GET-PROVIDER] Snacks provider available, using it` - 使用 Snacks
- `[GET-PROVIDER] Returning native provider` - 使用 Native

### Q: 如何强制使用特定的提供者？

A: 在配置中设置：
```lua
require("claudecode").setup({
  terminal = {
    provider = "native",  -- 或 "snacks"
    session_scope = "tab"
  }
})
```
